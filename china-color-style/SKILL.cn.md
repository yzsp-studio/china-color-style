# 中华传统色画风配色设计（中文版）

> 本文件是 `SKILL.md` 的中文对照，供人工阅读与修改。技能实际装载的是 `SKILL.md`。

## 一、这个技能做什么

把一段**故事前提**（朝代、人物、场景、情绪）或**一张已有的图**，变成可直接用于 AI 绘图的画风方案：

1. **风格判定** —— 选哪条朝代/流派脉络，并给出视觉层面的依据；
2. **配色方案** —— 具体的中国传统色（带真实 CMYK/RGB 色值）+ 主辅点缀比例；
3. **知识点** —— 服饰形制、用色等级限制、容易踩的坑；
4. **提示词** —— 按 主体/风格/材质/光影 分段的英文提示词，可直接粘贴；
5. **（反推模式）** —— 读一张已有图片，判断它的时代风格，指出问题并给修改建议。

**技能不会编造色值。** 每一个推荐的颜色都来自色卡数据集，并附带所属节气与书页。

## 二、数据在哪（随包自带，整个文件夹可拷走）

本技能包是**自包含**的：技能要读的东西都在它自己的 `data/` 里。
下表路径一律相对**技能所在目录**解析，所以文件夹拷到哪都能用。
可用 `${CHINA_COLOR_DATA}`、`${CHINA_COLOR_KNOWLEDGE}` 覆盖。

| 资产 | 路径（相对技能目录） | 用途 |
|---|---|---|
| 色卡数据 | `data/colors.json` | 色名、节气、cmyk、rgb、hex、书页、疑点、意象原文 |
| 色卡（可读版） | `data/色卡.md` | 按节气排版，含每色的颜色故事 |
| 色卡（表格版） | `data/colors.csv` | 同上，供表格软件查看 |
| 页码结构图 | `data/page-structure.json`、`data/书籍结构图.md` | 按页定位、引用出处 |
| 数据置信度 | `data/待复核清单.md` | 哪些色值是推定/未定 —— 引用前必看 |
| 历朝画风流派 | `data/knowledge/01-历朝画风流派.md` | 流派、笔法设色、材质、英文风格词 |
| 服饰形制与用色等级 | `data/knowledge/02-服饰形制与用色等级.md` | 形制、品色等级、AI 常见错误、快速校验表 |

（上游位置可用 `CHINA_COLOR_SRC` / `CHINA_KNOWLEDGE_SRC` 覆盖）。

### 数据诚实规则（不可违反）

- 384 色中 **375 条**有完整色值，其中 **19 条是推定补入**、**9 条仍缺**。`colors.json` 的 `flags`
  字段与 `待复核清单.md` 都标了出来。**推荐到这类颜色时要主动说明**（例："此色值在原书中未印全，为推定值"）。
- **不许四舍五入、不许"优化"、不许重新推算**色值。照 `rgb`/`cmyk` 原样引用。
- 引用出处时用 `chapter`（节气）与 `pages`（书页）。

## 三、模式 A：从故事前提出方案

**第 1 步 · 提取前提**：从用户的话里抓出 朝代（或"未指定"）、主体（人物/服装/场景/器物）、故事情绪、
是否要求混搭。**只问最少必要的追问。**

**第 2 步 · 有歧义就弹窗确认**：朝代、风格脉络、混搭程度真的分不清时，用 `ask_user_question`，
**绝不自己默默选**。给 2–4 个选项，推荐项放第一个并标 `（推荐）`，用**大白话**解释每个选项的差别
（用户是创作者，不是美术史学者）。值得问的三个维度：

- 风格脉络（如 唐·浓丽重彩 / 宋·素雅青绿 / 明·院体工细）；
- 演绎尺度（历史还原 / 艺术化演绎 / 跨时代混搭）；
- 用途决定配色预算（海报、人物立绘、场景概念图的冷暖与饱和度取舍不同）。

前提本身已经明确了就直接跳过弹窗。

**第 3 步 · 定风格并给依据**：读知识库 01，说清你要的具体视觉后果——笔法、设色方式、构图、
底调、材质，而不是空泛的赞美。同时点名该前提最容易踩的坑（用 01 里的"常见错误"）。

**第 4 步 · 从数据集里配颜色**：选 5–8 个色：1 个主色、2–3 个辅色、1–2 个点缀。两条硬约束：

- **等级约束**：给衣服上色前必查知识库 02。御用黄、某些紫与红曾是等级专用色，
  平民或低级官员穿上就是硬伤。
- **意象契合**：每个色都带 `meaning`（颜色故事）。优先选与剧情呼应的，并点出这层呼应——
  这是让推荐像"有人认真想过"而不是随机抽色的关键。

给出比例（可用 主色 60% / 辅色 30% / 点缀 10% 起步），每个色按
`色名 · hex · RGB · CMYK（节气）— 它在画面里的作用与意象` 写清。

**第 5 步 · 组装提示词**：按知识库 03 的骨架：主体 → 朝代风格 → 材质技法 → 配色 → 光影 → 镜头构图 → 画幅。
一条提示词里**只放一条风格脉络**，不要叠加互相矛盾的风格词（工笔＋写意、油画＋水墨）。
配色方向写在"配色"段而不是"风格"段。必要时给负向提示词。提示词用英文，用中文解释每段在干什么。

**第 6 步 · 按模板输出**，然后主动给下一步建议（变体、换节气、或做混搭版）。

## 四、模式 C：反推已有图片

触发：用户给图并问"这是什么朝代/风格""为什么感觉不对""怎么改"。

1. **看图**：当前模型支持图片输入时用 `read_image`。若被 harness 拒绝（有些会话跑的是纯文本模型），
   走视觉通道：`node scripts/analyze-image.mjs <图片路径> "<追问>"`，它会经路由器把图转给视觉模型并返回结构化 JSON。
   **说明你走的是哪条路。**
2. **精确取色**（确定性，不靠模型目测）：PNG 用 `node scripts/extract-palette.mjs <图片>`。
   格式不支持时脚本会明确说明，此时只能用视觉通道的近似值并标注为估计。
3. **映射回传统色**：`node scripts/match-colors.mjs "#a1b2c3,#d4e5f6"` 返回最近的库内传统色与 ΔE 距离——
   这样就能告诉用户"你这张图其实用到了哪几个历史色"。
4. **判定时代**：列出支持判断的证据与反证；画面确实模棱两可时，**至少给一个竞争假设**。
   绝不凭弱信号断言单一朝代。
5. **给修改方案**：形制/等级错误、时代错位、配色失衡、材质冲突——每条都给出正确描述与改后的提示词片段。

## 五、硬性规则

1. **不编色值、不编史实。** 数据集与知识库支撑不了的，就说"资料中没有"，不要凭记忆补。
2. **语义判断归你，不归脚本。** 脚本只取像素、算距离；"这个风格意味着什么"由你判断。
3. **给一个明确推荐。** 摆完选项后要说清你推荐哪个、为什么，用大白话。用户要的是决定，不是菜单。
4. **主动标注数据薄弱处**：推定/未定的色值，以及知识库里标了"存疑/推断"的说法，都要如实转达。
5. **尊重文化约束。** 等级色、吉凶色、宗教符号不是随意装饰；跨时代混搭的边界以知识库 04 为准。
6. **本技能不出图。** 它产出的是风格方向、配色、知识点与提示词。
